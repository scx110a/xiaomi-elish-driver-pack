## 1. Executive summary — where "no popup" comes from

"No popup" is **not one bug**. Four independent conditions can each produce it; a
diagnostic run must identify which one fired (see §5):

1. **UI selection (most likely for the reported test).** The module defaults to
   `prefer=tty` (`pam_bioauth.c:84, 1372-1386`), and `tty_open()` succeeds whenever the
   PAM caller has an openable terminal. `pamtester …` and `sudo` from a terminal always
   have `PAM_TTY=/dev/pts/N` → `ui_kind=UI_TTY` → **by design no GTK window**. The
   installed `/etc/pam.d/sudo` line is `pam_bioauth.so` with **no arguments**, so even
   the new module would stay TTY in a terminal; to get the overlay in a terminal session
   the line must become `pam_bioauth.so prefer=gui` (or the design decision must be
   documented). Handoff §6.1 lists this test as GUI but it cannot have shown a window
   from a terminal with the old module — the old module was also tty-first.
2. **Deployment skew (the new module is a landmine until all three files are replaced).**
   The audited PAM module **requires** a `{"event":"ready"}` handshake
   (`pam_bioauth.c:790-814, 1391-1403`), but the **installed** helper has zero `ready`
   emissions (`grep -c '"event": "ready"' /usr/local/libexec/bioauth-ui` → `0`; the
   workspace helper → `2`). Install module without the new helper and every GUI auth is
   killed by `ui_close()` after `ready_timeout` (default **3 s**) and falls back to TTY /
   `PAM_IGNORE` — the window flashes for ≤3 s and is gone, or never appears on a slow
   session. The installed daemon is also pre-`req`/pre-`session` (no cancel
   bookkeeping), so the new module's cancel scoping is silently ignored by the running
   daemon.
3. **helper_start failure** (`pam_bioauth.c:688-787`) returns `PAM_IGNORE` silently when:
   `g_helper` not executable, `/run/user/<$uid>` missing (GDM/pkexec before session
   login), no `WAYLAND_DISPLAY`/`DISPLAY` found (`:717-720`), or fork/socketpair fails.
   Only `plog` records it; with debug off there is no trace.
4. **GTK/ready failure** even when the helper starts: GTK init failure, no Gdk display,
   window never maps. The helper now logs these to `BIOAUTH_UI_LOG`/`/tmp/bioauth-ui.log`
   (module redirects its stdout/stderr there when `debug` is on, `:760-770`).

**Never reach for sudo/GDM until §6 passes.** The current installed stack is internally
consistent (old module + old helper + old daemon); mixing audited-HEAD artifacts with
the installed ones is the single fastest way to make authentication fail closed.

## 4. What is already fixed in the working tree (do not re-report)

Verified by reading the audited revision and by dynamic tests; these were real bugs in
the earlier 882/511/279-line versions:

- `Gtk.Window.close()` from GLib timeout hang → helper now uses `destroy()` in `_finish()`
  and quits via the `destroy` signal (`gui/bioauth-ui:739-766`); Lead's reproduction
  documented.
- `ready` handshake, map deadline, EOF handling, one-shot success timer, no duplicate
  success timer (`gui/bioauth-ui:454-467, 690-714, 754-766`).
- Password double-submit/empty submit guarded in the helper (`:639-663`); password values
  never logged by the helper (`:663, 798`).
- Helper fd/HUP busy-loop and daemon-fd POLLHUP handling fixed in PAM (`:601-604, 1206-1211, 1250-1257`).
- `SIGPIPE` risk on helper/daemon writes fixed with `MSG_NOSIGNAL` (`:535, 577, 1016, 1164`).
- Cancel-vs-verify race fixed **when the client sends `req`** (`daemon/bioauthd.py:148-167,
  213-248, 408-414`); dynamic test confirmed `cancel … hit=True` and
  `canceled (not counted)` during a live scan.
- TTY keyboard switch (`P`) / cancel (`Q`) implemented (`:391-414, 952-958`).
- Helper/TTY cleanup moved to a single `out:` block (`:1517-1521`); `ui_close()` reaps the
  helper with SIGTERM/SIGKILL.
- `password_tries=0`/`auth_timeout=0` handling, TTY password attempts, `status` fallback to
  password-only when locked: implemented.

### 5.2 Isolate the helper outside PAM (one command, no sensor)

```bash
python3 - <<'PY'
import os, socket, subprocess, time
parent, child = socket.socketpair()
subprocess.Popen(["/usr/local/libexec/bioauth-ui"], pass_fds=(child.fileno(),),
                 preexec_fn=lambda: os.dup2(child.fileno(), 3),
                 env={**os.environ, "XDG_RUNTIME_DIR": "/run/user/1000",
                      "WAYLAND_DISPLAY": "wayland-0",
                      "DBUS_SESSION_BUS_ADDRESS": "unix:path=/run/user/1000/bus"})
parent.settimeout(10); t0 = time.time()
try:
    while True:
        line = parent.makefile().readline()
        print("%.2fs %r" % (time.time() - t0, line))
        if '"ready"' in line: break
except Exception as e:
    print("no ready:", e)
PY
```
If this prints `ready` under the real session but PAM logs `helper not ready`, the
problem is the environment PAM gives the child (display/runtime-dir/uid drop), not GTK.
If it prints nothing, read `/tmp/bioauth-ui.log` (GTK/init) — this distinguishes
`helper_start` vs `GTK failure` definitively.

### 5.3 What each symptom class is *not*

- GUI window never appears but `ui_kind=1` in the log ⇒ **not** a helper/GTK bug; it is
  PAM_TTY/prefer selection (C1/P6).
- Window appears then vanishes at ~3 s ⇒ ready handshake/version skew (P1) or map
  deadline mismatch (P11), not helper crash.
- Window stays forever after success/cancel ⇒ stale helper (old close() bug) or fd3 not
  closed; verify installed helper hash, then re-run §5.2.
- No window and no `helper started` ⇒ `helper_start` failed at one of its 5 checks
  (`pam/pam_bioauth.c:699-725`), all of which are now plogged.

## 6. End-to-end acceptance gate before touching sudo/system PAM

All tests below run under a **private conf dir** (`pam_start_confdir`, `tests/pam_auth.py`)
+ **mock daemon** (`--socket /tmp/... --state /tmp/... --backend mock-*`) + `/tmp` build.
No `/etc/pam.d`, no real sensor, no `/var/lib/bioauth`, no `/usr/local/libexec`.

**6.0 Deployment consistency**
- `sha256sum build/pam_bioauth.so` == installed module; installed helper contains `ready`;
  installed daemon contains `pending_cancels`; `/etc/pam.d/sudo` line is exactly
  `pam_bioauth.so` + intended args (`prefer=gui` decision recorded).
- Rollback copy of `/etc/pam.d/sudo` exists and pkexec remains password-only.
- The three components come from the same build (add a `version=`/`build=` sha token,
  checked between module and helper at `ready`).

**6.1 GUI happy path (no tty, real helper)**
`pam_auth.py --confdir … --service … --user caitming` with `mock-success`:
window maps ≤2 s, module log shows `helper<- {"event":"ready"}`, `fingerprint resp ok=1`,
green `验证通过` visible ~1 s, `pam_authenticate rc=0`, and `pgrep -a bioauth-ui` is empty
after return (no orphan window). Repeat 10× (cold-start timing).

**6.2 TTY path (pty)**
Run inside `script`/pty so `PAM_TTY=/dev/pts/N`, `prefer=tty`: fingerprint success; `P`
during a scan switches to password without waiting for the scan; `Q` cancels; after each
path `stty -a` shows `icanon`/`echo` restored; no window spawns.

**6.3 Switch during scan (R16/R6)**
`mock-fail` + `BIOAUTH_MOCK_DELAY=3`: click 使用密码 during scan. Accept: daemon log
`cancel … hit=True` and `canceled (not counted)`; `fail_count` unchanged; password view
appears ≤1 s; correct password → `PAM_SUCCESS` + fingerprint re-enabled; no `Broken pipe`
noise needed for pass but D8 fix should silence it.

**6.4 Switch back (R17 deadlock)**
Password view → 使用指纹; accept: new scan starts ≤1 s after click (measure
`fingerprint req=…:2` timestamp − switch event timestamp; assert <1.5 s), no stuck
"正在切换…", max one spinner; if D3 not fixed this test will show a multi-second gap —
record it, do not weaken the test.

**6.5 Fail/lockout matrix**
- `max_failures=3`, `mock-fail`: exactly 3 mismatches → `指纹不匹配（1/3..3/3）` each
  stays visible ≥1.2 s → locked view, 使用指纹 hidden; wrong password does not unlock;
  correct password resets `fail_count=0`, unlock, fingerprint restored.
- `max_failures=0`: 5 mismatches never lock; UI must **not** say `n/3` (P5).
- `password_tries=3` vs `0`: 4 wrong passwords → error "已用完" vs still prompting.
- `auth_timeout=5`: idle → `验证超时` and PAM returns within ~7 s; daemon cancel hit;
  **no** failure counted.
- `fingerprint_timeout=8` idle/no-touch 3×: after D1 fix `fail_count` stays 0 and the
  message is 未检测到手指, never `指纹不匹配`/lock.

**6.6 Failure modes must fall back, not fail closed**
- Kill helper mid-scan (`kill -9 <bioauth-ui>`): module returns `PAM_IGNORE` quickly
  (helper-dead path), sudo-style stack falls through to `common-auth` (test with a
  bracketed test conf + `@include common-auth` in a private dir), no stuck window.
- Daemon stopped (`kill -STOP`/stop on private socket): auth completes (PAM_IGNORE) within
  ≤ `min(auth_timeout, 5 s)`; status read does not hang 60 s (P3).
- Cancel/close window: PAM returns `PAM_IGNORE` (P4), and the password stack is reached;
  WARNING: with the current installed `default=die` this test fails until P4 is fixed.
- Daemon socket unreadable / wrong socket path: `PAM_IGNORE`, password fallback.

**6.7 Secret-handling and logging**
- With `debug`, grep `/tmp/bioauth-pam.log` for `"value"`/`password`: must be absent
  (P2); file mode 0600, `O_NOFOLLOW`.
- `BIOAUTH_UI_LOG` must never contain a password (helper already redacts).
- No passwords/`password_b64` in journal or helper stdout.

**6.8 Only then, staged system integration (Lead/gui-dev own this)**
1. Install one consistent build (module+helper+daemon), keep rollback copies.
2. Point `/etc/pam.d/bioauth-test` at the private/mocked daemon socket and run the pty
   scenarios 6.2/6.5/6.6 through `pamtester`; still no sensor if possible.
3. One `sudo -k; sudo true` with `prefer=gui` and the new helper, watched while
   `journalctl -f -u bioauthd` + `tail -f /tmp/bioauth-pam.log`; confirm fail_count
   unchanged after a cancel; verify rescue channel (`pkexec`) still password-only.
4. Only after 1–3 pass: pkexec, then GDM (explicitly out of scope of this audit; GDM has
   no `/run/user/$uid` before login and the helper cannot be started there).

## 8. Recommended fix order (smallest safe sequence)

1. **P2** (stop logging secrets) before anyone enables `debug` on a system PAM line.
2. **P1 + P11 + §6.0** (one consistent build, real `ready` handshake with version token,
   ready timeout aligned with the helper map deadline) — this is the actual "no popup"
   unblock.
3. **P4 + C1** (cancel/timeout → `PAM_IGNORE`; decide `prefer=gui` for the sudo line and
   record it) so a failed popup always degrades to the password stack instead of
   locking the user out of the terminal.
4. **D1** (timeout must not count as failure) before any real-sensor idle testing.
5. **D3 + D2** (cancel completion/ownership; no cross-user cancel) before interactive
   switch-back testing.
6. **P3, P5, P6, P7, D5, D6, D8** hardening; P8/P9/P10/P12 and D4/D7/D9 after the E2E
   gate passes.
7. Keep GDM and pkexec untouched until §6.8 steps 1–3 pass (handoff §9 red lines).
